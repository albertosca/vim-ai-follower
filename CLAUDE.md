# vim-ai-follower — notes for Claude Code

Live "follower" editor for Claude Code: `PreToolUse`/`PostToolUse` hooks (`claude-follow hook pre|post`) snapshot a file, diff it, and animate the change into a real Vim (tmux backend, `send-keys`) or a Neovim (nvim backend, msgpack-RPC over pynvim). Ships as a Claude Code plugin (`.claude-plugin/`, `hooks/hooks.json`, slash commands in `commands/`).

## Commands

```sh
uv sync --extra dev --extra nvim            # a bare `uv sync` leaves pytest/mypy/pynvim missing
uv run ruff check src tests scripts && uv run ruff format --check src tests scripts   # lint.yml's scope
uv run mypy                                  # bare — pyproject's files = src + tests + scripts; CI runs the same
bash scripts/full_suite.sh   # runs scripts/validate_plugin.sh first; full suite, real tmux+vim+nvim, 100% gate; ~3170 tests (2322 unit + 848 integration, v0.5.0); 1468 took 27–28 min at load 7–22 (2026-10-05), not re-timed since — wait for load < 10, false timeouts above
uv run pytest -q -m "not integration"        # what CI runs (~1 min); coverage floor there is 98 (unit-only is ~99%)
uv run pytest -q -m "not integration" --junitxml=/tmp/u.xml && uv run python scripts/check_readme_facts.py --junit /tmp/u.xml   # facts check needs the unit JUnit; a "1100+"-style claim must be ≤ the real count and within 100
bash scripts/build_docs.sh && uv run python scripts/preview_docs.py 8000   # docs site at http://localhost:8000/vim-ai-follower/ (prod URLs rewritten to the working copy)
```

The project's bar is 100% branch coverage on the full suite; the coverage gate lives in the command line, not in pyproject. Integration tests (`@pytest.mark.integration`) need `tmux`, `vim` and `nvim` on PATH.

## Layout

- `src/vim_ai_follower/cli.py` — subcommands `start stop status hook pause interrupt speed-up speed-down toggle`; `commands.py` implements them, `keybindings.py` the tmux prefix keys.
- `hooks.py` — the hook orchestration (animate, interrupt hand-off loop, crash-fallback catch-up); `control.py` — signals + persisted pending animations (with `partial`); `binding.py` — the `session_id → (window, tmux server pid)` store that carries a session through a mid-run loss of `TMUX_PANE`; `state.py` — per-window follower state in `~/.cache/claude-vim-follower/`; `snapshot.py`/`diff.py` — before/after and the edit script; `animate.py` — tmux keystroke drivers; `tmux.py` — `TmuxPane` (send_line/send_text/send_hex) and `literal_argument`, the one place keys reach tmux.
- `backends/tmux_vim.py` (Vim via send-keys) and `backends/nvim.py` (Neovim via RPC) implement the `Follower` protocol in `backends/__init__.py`; `backends/nvim_connect.py` resolves the socket (adopt or split-launch) and bounds every connect/probe/RPC; `backends/nvim_prompt.py` keeps a plugin's hit-enter prompt from freezing an nvim follower.
- `take_over.py` — the tmux popup that asks an adopted editor's typing user before acting; `status_surface.py` — the per-backend cue surface (writer colour, hand-off/paused cue, restore), fed by `writer_cue.py`; `session.py` — tmux window identity or a standalone per-terminal id; `cache.py` — the one cache dir; `config.py` — config loading, speed/pace tables.
- Config: `~/.config/claude-vim-follower/config.json`; hook log: `~/.cache/claude-vim-follower/hook.log` (hooks never fail the tool call — problems go there).
- `qa/visual-battery.md` + `scripts/qa-check-N-*.sh` + `/qa-visual` — the manual visual QA battery (19 checks). `docs/superpowers/` is gitignored (private planning docs).

## Gotchas (each one cost a real bug)

Each line keeps the rule; the full record (measurements, residuals, the tests that pin it) is in `docs/superpowers/gotchas.md`, private to the maintainer's checkout. Read the section before changing the code a line names.
A new gotcha is one line here ending `→ docs/superpowers/gotchas.md#<slug>` plus a `<a id="<slug>"></a>` section there; `tests/scripts/test_claude_md_gotchas.py` pins pointer↔anchor (skipped without the private file, so CI never sees a broken pointer) and the 24,000-byte budget.

- **nvim API columns are BYTE offsets**: anything typing per character must carry `col += len(ch.encode())`; compare bytes in tests. The typing moves the follower's window found by handle (`_FOLLOWER_WINDOW_LUA`), never window 0; an adopted Edit records its window once, in `_run_ops` (`follower_window`). → docs/superpowers/gotchas.md#nvim-byte-columns
- **nvim follower buffers are never written to disk**: navigation is pure API, never `:edit`/`:drop`/`:buffer`; `ensure_showing` is the only entry point that shows disk content, `goto_file` never does; every new tab goes through `_show_in_new_tab` (by handle, never window 0 after `:tabnew`; failures undone by `_undo_new_tab`); only a follower `_is_dedicated()` proves dedicated types a first file in the current window; a Read re-reads only a CLEAN buffer (`b:vaf_synced_tick`). → docs/superpowers/gotchas.md#nvim-never-written
- **An adopted nvim is never locked `nomodifiable`**: guard every lock with `_locks_buffers()`, which fails CLOSED (`_is_dedicated()` via `state.owned_state`); `close_tab` and `user_readonly` fail closed the same way on both backends. The tmux backend locks adopted Vim like a dedicated one (intentional) and keeps claim bookkeeping; a hook whose state is gone after it locked sends `s:release_all` (`_release_if_stopped`). → docs/superpowers/gotchas.md#adopted-nvim-unlocked
- **Closing a tab in an ADOPTED editor never wipes the user's work**: a modified buffer is kept, a buffer the follower did not create is never wiped; "created"/"opened" are editor variables (`b:vaf_created`, `w:vaf_opened`), never cache state; for a window id use `gettabwinvar`, not `getwinvar()`. → docs/superpowers/gotchas.md#adopted-close
- **show_fresh renames only a buffer it has PROVEN is new** (tmux `s:rename`, nvim `_fresh_buffer`). Never "the current buffer after `:tabnew`". → docs/superpowers/gotchas.md#show-fresh-rename
- **tmux `:tab drop` ends with `:rewind`** (E37 on a dirty target): wrapped in `try/catch`. Never `:tab drop!`; swap dialogs are answered "edit anyway" (`SwapExists` on tmux, `swapfile=false` before `bufload` on nvim). → docs/superpowers/gotchas.md#tab-drop-rewind
- **`:tab drop` on an UNMODIFIED buffer re-reads it from disk**: tmux `goto_file` switches to a loaded buffer by NUMBER; the unlock says `noreadonly`; an adopted Vim's readonly/modifiable/'paste' are claims recorded and given back (`b:vaf_ro_ours`, `b:vaf_ma_ours`, `g:vaf_user_paste`, `s:note_user_lock`), and the follower's own option changes run only inside the dispatcher (`g:vaf_setting`), never a typed `:setlocal`. Never a changedtick stamp. A Read's clean-only re-read (`s:reload`) re-runs the swap search and carries the scoped SwapExists answer. Assert on the MIDDLE of an animation (`tests/test_integration_edit_no_reload.py`). → docs/superpowers/gotchas.md#tab-drop-reload
- **The tmux backend's calls are KEYED (`<F37>` + a call file) to a Vim that wrote its ready file, typed otherwise**: the Ex logic is `tmux_vim._VIM_SCRIPT` functions sourced by one define line (`_define_line`; a typed line ≤ 97 characters, up to six-digit pane ids); a path reaches Vim only through a handle file per call (`_path_handle`), never a fixed per-pane file; an acting call is confirmed by a separate `s:landed`, never by re-deriving the target's NAME; never pass `_vim_string(file_path)` into a typed line. → docs/superpowers/gotchas.md#keyed-calls
- **Every typed line and its Enter go in ONE `send-keys`** (`TmuxPane.send_line`); never join the Enter as `\; send-keys Enter`; a line that ran stays drawn, so the dispatcher ends with `redraw` + `echo ''`; animate.py's paced `:Nd`/`:N` pairs stay separate on purpose. → docs/superpowers/gotchas.md#one-send-keys
- **tmux ends a command at ANY argument that ends in `;`, and drops that `;`**: every user-content path goes through `send_text` (`tmux.literal_argument`); a user's saved binding is restored via `source-file` only after `_runs_only_its_binding`; pane titles go through `set_title` / `TmuxPane.title()`. → docs/superpowers/gotchas.md#tmux-semicolon
- **On tmux, whether a navigation landed is the landing check's to say, never an error's**: `s:goto` catches every error into `g:vaf_nav_error`; ownership marks are set after the try; an unanswered landing backs the pane off 30 s and defers closes and releases (`_defer_eviction`); `_with_unlocked` gives back the ANIMATED buffer's readonly by handle (`s:give_back`), never the current buffer's. → docs/superpowers/gotchas.md#landing-check
- **macOS Vim has 'fileignorecase' ON by default — never let it decide whether two names are one file**: lookups compare `resolve()`d `:p` names with `folds` (`_case_folds`), acting functions run with `&fic` off; Unicode normalization is matched by SPELLING (`_other_spellings`), never folded. → docs/superpowers/gotchas.md#fileignorecase
- **Renaming a buffer onto a path marks it "not edited"** (E13 on `:w`): show_fresh reads the file in and clears it in the SAME call (`s:rename`, `_READ_THEN_CLEAR_LUA`). → docs/superpowers/gotchas.md#rename-not-edited
- **Pause/interrupt signals are addressed to the animating PID**: never clear signals when a driver starts; a test that calls `request_pause` needs `mark_animating` first; P is a TOGGLE counted per press; never `display-popup -C`. → docs/superpowers/gotchas.md#signals-by-pid
- **Every nvim connect and request is bounded — except the typing — and an nvim that does not answer is BUSY, not gone**: liveness is `nvim_connect.probe_nvim`; a refusal is not absence; attach via `bounded_attach`, requests under `rpc_deadline`, `_drive` under `unbounded_requests`; close through `close_connection`; unit tests patch `nvim_connect.open_session`, never `pynvim.attach`; an adopted nvim waiting on its user is skipped (`hooks.adopted_user_pending`), a dedicated one never; nothing outside the follower's own `nvim-*.sock` is ever unlinked. → docs/superpowers/gotchas.md#nvim-bounded
- **An ADOPTED editor whose user is known to be TYPING is ASKED, never acted on silently** (`take_over.ask`: only a lone `y` after `ARM_SECONDS` is a yes; a decline is remembered in `<window>.declined`; the prompt goes raw with `TCSANOW`, never `tty.setraw`); a tmux Vim's mode is read without typing a key (`tmux_vim.typing_mode`); waiting at a prompt is not typing and is not asked (`tmux_vim.WAITING_REASONS`); a dedicated Vim is never read or asked; `stop` never asks; `mode-<pid>.txt`/`release-<pid>.txt` are deleted only for a dead pid, never by age. → docs/superpowers/gotchas.md#adopted-typing-asked
- **A tmux-split nvim is ready only when it answers AND has started** (`nvim_ready`), never when its socket file exists; a split that never answers is NEVER killed (`SplitNvimNeverAnswered`, launch backoff). → docs/superpowers/gotchas.md#split-ready
- **Interrupt on nvim leaves the half-typed line and rolls back the interrupted op**; `completed_count` counts whole lines/ops only; persisted `partial` strings are always newline-terminated. → docs/superpowers/gotchas.md#nvim-interrupt
- **`tmux capture-pane` shows the rendered screen, not the buffer**: dump the real buffer for content assertions; E37/ATTENTION only become blocking prompts under 51 columns (probe at 49). → docs/superpowers/gotchas.md#capture-pane
- **`tests/conftest.py`'s `headless_nvim` runs nvim with `-n` (no swap)**: swap tests need the fixture in `tests/test_nvim_integration_swap.py`; test nvims keep their state under a throwaway `XDG_STATE_HOME`, never the developer's `~/.local/state/nvim`; never point a test at `$TMUX`. → docs/superpowers/gotchas.md#headless-nvim-swap
- **`$TMUX` OVERRIDES `TMUX_TMPDIR`**: isolation needs `TMUX` unset AND a private `-S` socket (or `TMUX_TMPDIR`) AND `-f /dev/null`; target throwaway servers by socket AND by pid; extend `helpers.HERMETIC_VIMINIT` with `| …`, never replace it. → docs/superpowers/gotchas.md#tmux-isolation
- **A hook resolving to a `term-*`/`iterm-*` identity means the session lost `$TMUX_PANE`**: grep the log for `lost its tmux window identity` before concluding anything. → docs/superpowers/gotchas.md#lost-tmux-pane
- **`:bwipeout!` and `bufnr()` take a buffer-name PATTERN, not a path**: resolve a buffer NUMBER by walking the buffer list (nvim: `_buffer_number`, comparing REALPATHS). → docs/superpowers/gotchas.md#buffer-name-pattern
- **`open_files` means "these tabs exist"; `stale_files` means "this tab's buffer is out of sync"** (stale ⊆ open, enforced in `FollowerState.set`); a stale file's next Edit diffs from its recorded base when the buffer still holds it; every retype logs its reason. → docs/superpowers/gotchas.md#open-vs-stale
- **Every Python the follower starts runs with `-P`** (`hooks/hooks.json`, `bin/claude-follow`, the take-over popup). Never `-I`. → docs/superpowers/gotchas.md#python-dash-p
- **A tmux keybinding embeds an absolute path and is server-global and persistent**, so it must name a path that outlives the process that bound it (`keybindings._durable_wrapper`); `git rev-parse --git-common-dir` answers RELATIVE from a subdirectory. → docs/superpowers/gotchas.md#durable-keybinding
- **Keybinding ownership lives in `keybindings-owner.json`**: `tmux list-keys` pads columns — parse split tokens, never a `" prefix P "` substring. → docs/superpowers/gotchas.md#keybinding-owner
- **`compute_edit_script` emits ops bottom-up**; a whole-buffer delete is always the last op. → docs/superpowers/gotchas.md#bottom-up-ops
- **A UTF-8 BOM lives in 'bomb', not the buffer**: type `without_bom(...)`, but the hand-off wait compares disk with the real `after`. → docs/superpowers/gotchas.md#bom
- **A CRLF file is `fileformat=dos` in both editors: its buffer lines carry no CR**: read compared files as bytes, never `read_text()`; split on LF only (`diff.text_lines`), never `str.splitlines()`; a mixed file's typed lines carry their CRs; a dos buffer an Edit makes mixed is typed `backends.typed_onto(before, after)`. → docs/superpowers/gotchas.md#crlf
- **A Read holds the animating slot for its whole navigation** (`try_acquire_animating(state="finishing")`). → docs/superpowers/gotchas.md#read-holds-slot
- **`claude-follow stop` clears the state FIRST, then tears down best-effort, and leaves a tombstone**: every teardown step is logged, never raised; `stop` always exits 0; an adopted editor is the user's and is never closed; every state records its tmux server (`server_pid`) and a legacy one is never adopted; `stop` acts only on proof (`proven_here`); a dedicated nvim's pane is found by its exact start command, never the origin, never an adopted pane. → docs/superpowers/gotchas.md#stop-order
- Test-side: assert on the specific call, not `assert_called_once`. → docs/superpowers/gotchas.md#assert-specific-call
- **Run the full suite alone**; rerun a failing test alone before calling it a regression. → docs/superpowers/gotchas.md#full-suite-alone
- **QA scripts (`scripts/qa-check-*.sh`) must run from inside a tmux pane** and background a hook with `> log 2>&1 &`, never `| tee`. → docs/superpowers/gotchas.md#qa-scripts-in-pane
- **`conftest.py`'s autouse `no_pid_ancestry_walk` only reaches IN-PROCESS code**: a test that runs the hook as a SUBPROCESS needs a private socket (`@pytest.mark.pid_walk` opts in). → docs/superpowers/gotchas.md#pid-walk-in-process
- **`tmux` and `keybindings` share one `subprocess` module object**: resolve any expected path INSIDE the patch. → docs/superpowers/gotchas.md#shared-subprocess
- **Coverage is blind to subprocess execution**: never chase it with `# pragma: no cover`. → docs/superpowers/gotchas.md#coverage-blind-to-subprocess
- **Worktrees:** tool-created worktrees may start from a stale `origin/main`; `docs/superpowers/` edits made inside one never come back via merge. → docs/superpowers/gotchas.md#worktrees

## Release

`claude plugin update` is gated on `.claude-plugin/plugin.json`'s `version`, not on git. Every user-visible fix: bump the version, commit, then `claude plugin tag --push` (creates `vim-ai-follower--vX.Y.Z`; refuses a dirty tree — never `--force`). CI is `ci.yml` (unit suite + coverage floor) and `lint.yml` (ruff + mypy); the README coverage badge is static — update it in the same commit when the measured number moves.

- `scripts/validate_plugin.sh` (run first by `full_suite.sh`, skipped without `claude` on PATH) is `claude plugin validate --strict .` tolerating exactly one warning: "CLAUDE.md at the plugin root is not loaded as project context" — this file is the repo's notes for Claude Code, not plugin context, so it stays. Any error or other warning fails. Not in CI: it needs the Claude Code CLI.
- `git fetch` before pushing main: Dependabot/deps PRs merge on GitHub (`uv.lock` bumps), so origin/main moves without you; merge it, rerun lint + unit on the merged tree, then push.
- `docs.yml` builds with `uv run`, and `[tool.uv] python-preference = "only-system"` + `.python-version` (3.14) means the job must install THAT Python (`python-version-file`); with 3.11 every `uv run` failed. Pages is enabled with `gh api -X POST repos/albertosca/vim-ai-follower/pages -f build_type=workflow` (done 2026-10-05).
- The GitHub runner is slower than the Mac: a thread race the local suite never lost failed CI (the nvim watchdog counted a dismissal after its settle wait, c6b0dc5). A timing-dependent unit test must make the slow interleaving deterministic, not hope for the fast one.
- The runner's pytest tmp path is 80–88 characters (macOS `/private/tmp/…` is shorter), and a define line's form follows its path's length (the guard drops past 97): a unit test that asserts on a define line must patch `tmux_vim._home_relative` (be12366). Reproduce CI's length with `--basetemp=/tmp/pyt-of-r/pytest-0` (create the parent first).
- The social preview (`assets/site/social-preview.svg` → `.png`) carries its own "N+ unit tests" line that the facts check does not read; re-render it when the README number moves (`"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless --hide-scrollbars --user-data-dir=<scratch> --screenshot=<out>.png --window-size=1280,640 file://$PWD/assets/site/social-preview.svg`) and re-upload it (GitHub Settings → Social preview, web UI only); `gh repo view --json usesCustomOpenGraphImage,openGraphImageUrl` says whether GitHub serves it.
