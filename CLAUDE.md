# vim-ai-follower — notes for Claude Code

Live "follower" editor for Claude Code: `PreToolUse`/`PostToolUse` hooks (`claude-follow hook pre|post`) snapshot a file, diff it, and animate the change into a real Vim (tmux backend, `send-keys`) or a Neovim (nvim backend, msgpack-RPC over pynvim). Ships as a Claude Code plugin (`.claude-plugin/`, `hooks/hooks.json`, slash commands in `commands/`).

## Commands

```sh
uv sync --extra dev --extra nvim            # a bare `uv sync` leaves pytest/mypy/pynvim missing
uv run ruff check src tests && uv run ruff format --check src tests
uv run mypy                                  # bare — pyproject's files = src + tests; CI runs the same
bash scripts/full_suite.sh   # full suite, ~7 min, real tmux+vim+nvim; its gate is the 100% the README claims
uv run pytest -q -m "not integration"        # what CI runs (~15 s); coverage floor there is 98 (unit-only is ~99%)
bash scripts/build_docs.sh && uv run python scripts/preview_docs.py 8000   # docs site at http://localhost:8000/vim-ai-follower/ (prod URLs rewritten to the working copy)
```

The project's bar is 100% branch coverage on the full suite; the coverage gate lives in the command line, not in pyproject. Integration tests (`@pytest.mark.integration`) need `tmux`, `vim` and `nvim` on PATH.

## Layout

- `src/vim_ai_follower/cli.py` — subcommands `start stop status hook pause interrupt speed-up speed-down toggle`; `commands.py` implements them, `keybindings.py` the tmux prefix keys.
- `hooks.py` — the hook orchestration (animate, interrupt hand-off loop, crash-fallback catch-up); `control.py` — signals + persisted pending animations (with `partial`); `binding.py` — the `session_id → (window, tmux server pid)` store that carries a session through a mid-run loss of `TMUX_PANE`; `state.py` — per-window follower state in `~/.cache/claude-vim-follower/`; `snapshot.py`/`diff.py` — before/after and the edit script; `animate.py` — tmux keystroke drivers.
- `backends/tmux_vim.py` (Vim via send-keys) and `backends/nvim.py` (Neovim via RPC) implement the `Follower` protocol in `backends/__init__.py`.
- Config: `~/.config/claude-vim-follower/config.json`; hook log: `~/.cache/claude-vim-follower/hook.log` (hooks never fail the tool call — problems go there).
- `qa/visual-battery.md` + `scripts/qa-check-N-*.sh` + `/qa-visual` — the manual visual QA battery (19 checks). `docs/superpowers/` is gitignored (private planning docs).

## Gotchas (each one cost a real bug)

- **nvim API columns are BYTE offsets** (`buf_set_text`, `win_set_cursor`). Anything typing per character must carry `col += len(ch.encode())`. In tests compare bytes: pynvim decodes with `surrogateescape`, so corruption looks like an ordinary string mismatch.
- **nvim follower buffers are never written to disk.** Navigation must use pure API (`list_tabpages`/`win_get_buf`/`set_current_win`), never `:edit`/`:drop`/`:buffer` — those hit Vim's abandon check (E37) or silently reload from disk. `ensure_showing` is the only disk-reading entry point; `goto_file` never reads disk. On a Read it re-reads an open buffer only when CLEAN: unmodified, or its `b:changedtick` still equal to the `b:vaf_synced_tick` `_drive` stamps at a completed animation (follower text is always 'modified'); any user edit moves the tick. nvim's `:edit!` of a buffer that already has a swap runs no new swap search (measured, unlike Vim), so that re-read needs no swap toggle.
- **An adopted nvim (`adopt_existing`) is never locked `nomodifiable`** — animation or navigation. Guard every lock with `if not self._is_adopted()`. The tmux backend locks adopted Vim like a dedicated one; that asymmetry is intentional.
- **Closing a tab in an ADOPTED editor never wipes the user's work** (eviction past `max_tabs`, and `claude-follow stop`; final review C1, 2026-10-05: a Read put the user's own modified buffer into `open_files` and five Reads later `bwipeout!` took it). tmux `s:evict` / nvim `_EVICT_LUA`: a modified buffer (nvim: not clean by `_IS_CLEAN_LUA`) is "kept"; a buffer the follower did not create is never wiped — only a window the follower opened for it is closed, and the follower's Read lock is given back (`s:release`); a clean buffer the follower created is wiped, so max_tabs still caps its own tabs. "Created"/"opened" are editor variables (`b:vaf_created`, `w:vaf_opened`), never cache state: they must die with the editor, or a restarted adopted Vim's buffers would read as the follower's. Dedicated followers keep the plain `s:wipe`. Vim's `getwinvar()` takes a window NUMBER in the current tab — for a window id use `gettabwinvar` over `win_id2tabwin()` (a `getwinvar(id, …)` silently read '' and closed nothing).
- **show_fresh renames only a buffer it has PROVEN is new** (final review I1: a user `BufEnter … | tabfirst` on `:tabnew` made the rename name the USER's buffer, which the landing check then confirmed, since the rename makes any buffer "the target"). tmux `s:rename`: after `tabnew`, a number above every earlier one, unnamed, unmodified — else `s:drop_fresh` and no landing (NavigationFailed). nvim `_fresh_buffer`: `create_buf` + name by handle, put in the window of the tab the tabnew ADDED (found by tabpage handle), then require it current. Never "the current buffer after `:tabnew`".
- **tmux `:tab drop` ends with `:rewind`, whose abandon check runs on the buffer it just landed on** → E37 on a dirty target; wrapped in `try/catch`. Never `:tab drop!` (discards unsaved content). Swap-file dialogs are auto-answered "edit anyway" via a scoped `SwapExists` autocmd (tmux) / buffer-local `swapfile=false` before `bufload` (nvim) — `SwapExists` does not fire under `bufload`.
- **`:tab drop` on an UNMODIFIED buffer re-reads it from disk** (its trailing `:rewind` is an `:edit`). Every completed animation ends in `:e!`, so the buffer is clean, and by `hook post` Claude has already written the finished file: an Edit flashed the final content and then typed the diff on top of it (duplicated lines, def count 1 → 3 → 5 → 3), hidden from every end-state test because the relock's `:e!` snaps it back (bug since 3923bd0, fixed 2026-09-23). tmux `goto_file` now switches to a loaded buffer by NUMBER (`win_gotoid` / `:tab sbuffer N`) and keeps `:tab drop` only for a file no buffer holds. The old reload was also silently clearing `readonly`, so the animation unlock now says `noreadonly` itself — without it, `o` on a buffer show_fresh/ensure_showing locked raises W10 and a hit-enter prompt eats the whole animation. In an ADOPTED Vim only (a dedicated follower's readonly is never the user's), the follower marks its own claim on the option in `b:vaf_ro_ours` (1 = its readonly lock, 2 = unlocked for an animation), notes the user's value in `b:vaf_user_ro` before each of its readonly-changing steps while it holds no claim, and `s:restore_readonly` puts the user's back after the relock, at an interrupt and in `hand_over`. Never a changedtick stamp: a reload (`:checktime` under 'autoread') moves the tick but keeps the follower's readonly, and it was handed back as the user's (E45 on the cue's `:w`). The restore also writes `user_readonly`'s answer to a file, so the `:w!` hand-off cue costs no keystrokes of its own. `tests/test_integration_edit_no_reload.py` watches the buffer MID-animation with a VIMINIT-loaded Vim timer (no keys sent) — assert on the middle, not just the end. The one navigation that SHOULD re-read is a Read (`ensure_showing`): it adds a clean-only `silent edit` (`s:reload`) so a file rewritten by Bash/`sed -i`/`git checkout` isn't shown stale — and that `:edit` re-runs the swap search and raises ATTENTION on its own when the user's Vim owns `.swp`, so it carries the same scoped SwapExists answer.
- **The tmux backend types only short calls — its Ex logic is Vim functions defined once per Vim, and the target's path is never on a typed line.** Vim echoes every typed command on its command line: the demo flashed the absolute path on every edit (2026-09-29), and later a 12–30-row block of Vim script (the ~1,500-character goto line, 2026-10-05). The logic lives in `tmux_vim._VIM_SCRIPT` (legacy Vim script, every function `abort` so an error stops it where it used to stop the rest of a typed line, helpers script-local, ONE global dispatcher `VafFollower_<6 hex>` named after a hash of the script + cache dir), written to `CACHE_DIR/vaf-<hash>.vim` and sourced by `_define_line` (`:if !exists('*VafFollower_…')|sil! so ~/.cache/…|endif`), which every entry point that may be first sends before its calls — so a Vim that lost the functions (`:delfunction`, an adopted Vim restarted in the same shell: same pane pid) gets them on the very next call; the script deletes older dispatchers, but only one Vim says was set from `vaf-<its own hash>.vim` (`:verbose function`'s path — its words are translated — so a user's own `VafFollower_123abc()` survives). Each call line is `:if exists('*Fn')|call Fn('op',…)|endif`, no spaces around the bars: two screen rows at 49 columns is ≤ 97 typed characters with the `:` (96 from `getcmdline()`; measured on Vim 9.2, `:` + 97 puts the cursor on a third row), the longest is show_fresh's rename, whose handle carries the pane id, and it must fit up to six-digit pane ids (pinned by `tests/test_integration_cmdline_paths.py` and the unit `test_every_typed_call_fits_two_screen_rows`), so a Vim without them runs nothing and raises no E117. A path reaches Vim through a handle file per call (`_path_handle`, `p<pane>-<6 hex>`, also the call's token): `s:read` reads it byte-exact (`filereadable()` + `readfile(…, 'b')`, never a try around the read) and `delete()`s it (never a fixed per-pane file — Vim runs a line after the send returns, so an eviction and the next pre-wipe would share it; unread handles are swept after 600 s, any pane's). A missing handle reads as '' and every function then acts on nothing; a call that must ACT (`s:goto`, `s:rename`) is followed by an Escape pair and a separate `s:landed` call (never the acting call's tail — a goto that opens a second tab from one leaves a prompt that swallows the next line's first screen row) that answers `landed-<pane>.txt` only when the current buffer is the one the acting call recorded landing on (`g:vaf_landed`, by NUMBER, next to the token `g:vaf_k`), and Python sends nothing more without it (`NavigationFailed`, which the hooks log in one line and skip the edit, marking the file stale) — a failed goto once let a Read lock, and an Edit's relock `:e!` wipe, the user's own unsaved buffer. Never confirm by re-deriving the target's NAME: Vim navigates by file identity (`:tab drop` lands on an existing buffer opened through a file symlink, e.g. a dotfiles `~/.vimrc`, or under a case variant on macOS), and a name check failed every Read of such a file after 10 s. The script names the cache dir in full (`s:dir`; a file, never echoed), so only the define line types a path: `~/.cache/…` when the pane's Vim shares the hook's HOME — asked once per pane pid (`_vim_shares_home`, `:silent! call writefile([], expand(…, 1))`; the `1` (nosuf) is load-bearing, since a `wildignore=*/.cache/*` makes a plain `expand()` return ''; `:source ~/…` itself ignores 'wildignore', measured; an adopted pane's pid is the user's SHELL, so no answer with the path handle still unread drops a "yes" and the next call asks again), else the absolute path (through `fnameescape()` unless it is plain). Commands that print a file's name are `silent` (`:file`, `:tab drop`, `:tab sbuffer`), errors still showing. `tests/test_integration_cmdline_paths.py` logs every `CmdlineChanged` plus `:messages` — never pass `_vim_string(file_path)` into a typed line.
- **macOS Vim has 'fileignorecase' ON by default — never let it decide whether two names are one file.** On a case-sensitive volume `Readme.md` and `README.md` are two files, and with it on the lookups, `:tab drop README.md` and `:file README.md` all took the one for the other (an Edit typed into the sibling, a retype wiped it, an adopted Read locked the user's modified sibling; measured 2026-09-29 on a Case-sensitive APFS image). The tmux backend's lookups (`s:find`/`s:same_file`) compare `resolve()`d `:p` names with `folds`, which Python decides per path from the FILESYSTEM (`_case_folds`: is the swapcase spelling the same file); the acting functions run with `&fic` off (restored in `finally`), so Vim matches by inode; a landing counts only when the current buffer IS the target by that comparison (a hard link lands "elsewhere"). `resolve()` of a symlink loop raises E655, so every resolve is in its own try (`s:resolved`) inside a `:for` — one looping buffer in a `filter()` aborted every lookup. `tests/test_integration_same_file.py` attaches a real case-sensitive disk image (hdiutil; skipped without it).
- **Renaming a buffer onto a path marks it "not edited"** (Vim `:file`, nvim `buf_set_name`): a plain `:w` over the existing file then fails with E13, which made the hand-off cue's ":w releases" false for an interrupted Write. show_fresh reads the file in and clears it in the SAME call / nvim request (tmux `s:rename`, nvim `_READ_THEN_CLEAR`: `noautocmd silent! edit!` then `silent! %d _`), so it is never on screen; this is the one `:edit` the nvim backend runs outside ensure_showing, on the empty buffer it just created. The read also restores the "changed since reading it" check a not-edited buffer skipped.
- **Pause/interrupt signals are addressed to the animating PID** (`control._request` writes the live marker's PID; `check_signal` obeys only its own and drops the rest as stale). Never clear signals when a driver starts: the hook shows "running" from `try_acquire_animating` on, navigates first, and a start-of-driver `clear_signals` wiped every P pressed in that gap (lost 5 of 5 runs, fixed 2026-09-28). A test that calls `request_pause` needs a live marker first (`mark_animating`), or nothing is written.
- **Interrupt on nvim leaves the half-typed line and rolls back the interrupted op**; `completed_count` counts whole lines/ops only. Persisted `partial` strings are always newline-terminated (`diff.apply_ops` terminates).
- **`tmux capture-pane` shows the rendered screen, not the buffer.** For content assertions dump the real buffer (`:w!` to a scratch file on Vim, `buf_get_lines` over RPC on nvim). E37/ATTENTION only become blocking prompts under 51 columns — probe at the follower pane's real width (49).
- **`tests/conftest.py`'s `headless_nvim` runs nvim with `-n` (no swap)** — anything swap-related needs the no-`-n` fixture in `tests/test_nvim_integration_swap.py`. `tmux_session` isolates from your real tmux server; never point a test at `$TMUX`.
- **`$TMUX` OVERRIDES `TMUX_TMPDIR`.** `TMUX_TMPDIR=/tmp/mine tmux kill-server` run from inside a tmux pane kills the REAL server, silently and with no output — measured 2026-09-22, when it took down a live 20-window server mid-session. Isolation needs `TMUX` unset (`env -u TMUX`, or `monkeypatch.delenv` as `tmux_session` does) — setting `TMUX_TMPDIR` alone is not isolation. This bites hand-typed teardown even when the scripts get it right, so target throwaway servers by socket AND by pid. The converse bites too (measured 2026-09-28): unsetting `TMUX` alone is not isolation either — a bare `tmux …` (or backend code run in-process, e.g. `TmuxVimFollower`, whose `tmux send-keys -t %1` names no socket) then talks to the DEFAULT server, which is the user's real one; a review probe typed into the real pane `%1` that way. Every hand-run or in-process tmux call needs a private `-S` socket (or `TMUX_TMPDIR` to a private dir) AND `TMUX` unset.
- **A hook resolving to a `term-*`/`iterm-*` identity means the session lost `$TMUX_PANE`** (the `bg-spare` harness bug), not that the hook never ran. Before concluding anything from a quiet log, grep it for `lost its tmux window identity`, and remember `claude-follow status` answers about the identity the CALLER resolves to — from a session without `TMUX_PANE` it will say "no follower" while the real window's follower is alive.
- **`:bwipeout!` and `bufnr()` take a buffer-name PATTERN, not a path.** `[…]` is a character class and `{…}` a multi, so a real file like `app/[slug]/page.tsx` matches nothing and `:silent!` swallows the E94 — the "evicted" buffer survives and, if the caller navigated first, `:tab drop` even added a tab for it. Resolve a buffer NUMBER by walking the buffer list and wipe that — tmux compares `fnamemodify(…, ':p')` on both sides; nvim (`_buffer_number`, one `exec_lua`) must compare REALPATHS, because nvim stores names with a symlinked directory resolved (`/tmp` → `/private/tmp`) and `:p` does not. With a pattern-sibling open, nvim's `bufnr('app/[slug]/page.tsx')` returns `app/s/page.tsx` — the wrong buffer, not merely none.
- **`open_files` means "these tabs exist"; `stale_files` means "this tab's buffer is out of sync".** They were one field until 2026-09-22, and the busy-animation-slot branch — which must force a full retype without touching a pane another hook is animating — could only say it by dropping the file, which orphaned the tab past `max_tabs`. Invariant: stale ⊆ open, enforced in `FollowerState.set` (not in `touch_open_files`, because `cmd_toggle` zeroes `open_files` without going through the helper).
- **A tmux keybinding embeds an absolute path and is server-global and persistent**, so it must name a path that outlives the process that bound it: `keybindings._durable_wrapper` re-anchors out of a linked worktree into the main checkout. Beware that `git rev-parse --git-common-dir` answers RELATIVE from a subdirectory while `--git-dir` is absolute — comparing them raw calls every ordinary checkout a worktree.
- **Keybinding ownership lives in `keybindings-owner.json`.** `claim()` re-points on same-installation changes (the plugin root is version-stamped, so the installation id is its parent — recognized from the path's `plugins/cache/<mkt>/<plugin>/<version>/bin` shape too, because `/start` runs in the Bash tool, which has NO `CLAUDE_PLUGIN_ROOT`), takes from a dead owner or one whose record survived a tmux restart but holds no key, and keeps a live foreign one that does hold them (`start --take-keys` forces). `start`/auto-open pass `repair=True` because a restarted tmux server drops bindings while the cache still names us; the per-hook heal does not. `tmux list-keys` pads columns with runs of spaces — parse split tokens, never a `" prefix P "` substring.
- **`compute_edit_script` emits ops bottom-up** (later lines first), so line numbers stay valid as ops apply; a whole-buffer delete is always the last op.
- **A UTF-8 BOM lives in 'bomb', not the buffer** (Vim and nvim alike), while the snapshot keeps U+FEFF (final review I2: every BOM file probed "differs"). `buffer_forms` also accepts the BOM-less form; `_animate_edit` types and builds partials from `without_bom(...)`, but the hand-off wait compares disk with the real `after` — stripping it there reads every poll as a user save.
- **A Read holds the animating slot for its whole navigation** (`try_acquire_animating(state="finishing")`, skip on busy, release in `finally`; final review M2). A check-then-navigate let an Edit take the slot between the Read's sends, and the Read's Escape pair then ended the Edit's insert mode. "finishing", so P/S pressed meanwhile get "nothing to pause", not a signal no driver reads.
- Test-side: assert on the specific call, not `assert_called_once` — exact call counts break whenever a neighbor adds an API read.
- **Run the full suite alone.** Integration tests spawn real tmux servers and nvims; two suites in parallel (or a parallel agent's) push load past 10 and produce false timeouts — rerun the failing test alone before calling it a regression.
- **QA scripts (`scripts/qa-check-*.sh`) must run from inside a tmux pane** (`$TMUX_PANE` guard) and background a hook with `> log 2>&1 &`, never `| tee` — a pipe makes the shell wait and the interrupt/pause you're testing never lands. Finish with `source scripts/qa-lib.sh && qa_teardown`.
- **`conftest.py`'s autouse `no_pid_ancestry_walk` only reaches IN-PROCESS code.** It stubs `session._tmux_panes_by_pid` so the suite doesn't resolve to whatever window the developer is sitting in — but a test that runs the hook as a SUBPROCESS bypasses it and the pid walk hits the real tmux server. Point such a test at a private socket and fire the blind half from the pytest process, not from inside a pane, or it passes for the wrong reason. Opt in with `@pytest.mark.pid_walk`.
- **`tmux` and `keybindings` share one `subprocess` module object**, so patching `vim_ai_follower.tmux.subprocess.run` silently intercepts `keybindings`' `git rev-parse` too. Resolve any expected path INSIDE the patch, or expectation and code under test see different worlds.
- **Coverage is blind to subprocess execution**, so the e2e CLI tests add none — expect the percentage not to move, and never chase it with `# pragma: no cover`. To read a real buffer from an integration test, dump it with Vim's `writefile()` (or `buf_get_lines` over RPC): delete the dump first and wait for a sentinel prefix so a stale or half-written read can't pass for an answer, and retry — a loaded machine swallows the ESC pair.
- **Worktrees:** tool-created worktrees may start from a stale `origin/main` — check `git rev-parse HEAD` against local `main` first. `docs/superpowers/` is gitignored, so edits made there inside a worktree never come back via merge: copy them to the main checkout before removing the worktree.

## Release

`claude plugin update` is gated on `.claude-plugin/plugin.json`'s `version`, not on git. Every user-visible fix: bump the version, commit, then `claude plugin tag --push` (creates `vim-ai-follower--vX.Y.Z`; refuses a dirty tree — never `--force`). CI is `ci.yml` (unit suite + coverage floor) and `lint.yml` (ruff + mypy); the README coverage badge is static — update it in the same commit when the measured number moves.
