# vim-ai-follower — notes for Claude Code

Live "follower" editor for Claude Code: `PreToolUse`/`PostToolUse` hooks (`claude-follow hook pre|post`) snapshot a file, diff it, and animate the change into a real Vim (tmux backend, `send-keys`) or a Neovim (nvim backend, msgpack-RPC over pynvim). Ships as a Claude Code plugin (`.claude-plugin/`, `hooks/hooks.json`, slash commands in `commands/`).

## Commands

```sh
uv sync --extra dev --extra nvim            # a bare `uv sync` leaves pytest/mypy/pynvim missing
uv run ruff check src tests && uv run ruff format --check src tests
uv run mypy                                  # bare — pyproject's files = src + tests; CI runs the same
bash scripts/full_suite.sh   # runs scripts/validate_plugin.sh first; full suite, real tmux+vim+nvim, 100% gate; 1468 tests took 27–28 min at load 7–22 (2026-10-05) — wait for load < 10, false timeouts above
uv run pytest -q -m "not integration"        # what CI runs (~1 min); coverage floor there is 98 (unit-only is ~99%)
uv run pytest -q -m "not integration" --junitxml=/tmp/u.xml && uv run python scripts/check_readme_facts.py --junit /tmp/u.xml   # facts check needs the unit JUnit; a "1100+"-style claim must be ≤ the real count and within 100
bash scripts/build_docs.sh && uv run python scripts/preview_docs.py 8000   # docs site at http://localhost:8000/vim-ai-follower/ (prod URLs rewritten to the working copy)
```

The project's bar is 100% branch coverage on the full suite; the coverage gate lives in the command line, not in pyproject. Integration tests (`@pytest.mark.integration`) need `tmux`, `vim` and `nvim` on PATH.

## Layout

- `src/vim_ai_follower/cli.py` — subcommands `start stop status hook pause interrupt speed-up speed-down toggle`; `commands.py` implements them, `keybindings.py` the tmux prefix keys.
- `hooks.py` — the hook orchestration (animate, interrupt hand-off loop, crash-fallback catch-up); `control.py` — signals + persisted pending animations (with `partial`); `binding.py` — the `session_id → (window, tmux server pid)` store that carries a session through a mid-run loss of `TMUX_PANE`; `state.py` — per-window follower state in `~/.cache/claude-vim-follower/`; `snapshot.py`/`diff.py` — before/after and the edit script; `animate.py` — tmux keystroke drivers.
- `backends/tmux_vim.py` (Vim via send-keys) and `backends/nvim.py` (Neovim via RPC) implement the `Follower` protocol in `backends/__init__.py`.
- Config: `~/.config/claude-vim-follower/config.json`; hook log: `~/.cache/claude-vim-follower/hook.log` (hooks never fail the tool call — problems go there).
- `qa/visual-battery.md` + `scripts/qa-check-N-*.sh` + `/qa-visual` — the manual visual QA battery (19 checks). `docs/superpowers/` is gitignored (private planning docs).

## Gotchas (each one cost a real bug)

- **nvim API columns are BYTE offsets** (`buf_set_text`, `win_set_cursor`). Anything typing per character must carry `col += len(ch.encode())`. In tests compare bytes: pynvim decodes with `surrogateescape`, so corruption looks like an ordinary string mismatch.
- **nvim follower buffers are never written to disk.** Navigation must use pure API (`list_tabpages`/`win_get_buf`/`set_current_win`), never `:edit`/`:drop`/`:buffer` — those hit Vim's abandon check (E37) or silently reload from disk. `ensure_showing` is the only entry point that shows disk content; `goto_file` never does (it creates a missing buffer empty: its read-then-clear, the same `_READ_THEN_CLEAR_LUA` as show_fresh, only makes the buffer "edited" so a plain `:w` saves it). Every new tab is opened by `_show_in_new_tab`, which finds the tab by HANDLE (never window 0 after `:tabnew`: a user autocmd that jumps tabs on TabNew/BufNew/BufEnter makes window 0 the user's), gives every window that existed before the tabnew, in ANY tab, its own buffer back when an early jump (TabNew/BufNew/WinNew/BufAdd) dropped the tabnew's scratch into it (recorded by handle before the tabnew; a window the follower created is never in the record), wipes the tabnew's scratch buffer (`_wipe_if_scratch`, which first asks `buf_is_valid`: a replaced buffer may already be gone, since a start screen's `:enew` reuses the startup buffer 1 and sets `bufhidden=wipe`, and asking its name crashed every first Edit into a dedicated nvim with such a config), and turns a refused switch (E37 under 'nohidden') into NavigationFailed. Only a follower `_is_dedicated()` proves dedicated may type a first file in the current window: show_fresh opens a tab in an adopted (or state-gone) nvim whatever `in_new_tab` says, because an adopted nvim's state never sets `shown_any`. On a Read it re-reads an open buffer only when CLEAN: unmodified, or its `b:changedtick` still equal to the `b:vaf_synced_tick` `_drive` stamps at a completed animation (follower text is always 'modified'); any user edit moves the tick. The stamp is one `exec_lua` (`_STAMP_IF_EXPECTED_LUA`) that stamps only when the buffer holds exactly the lines the run was meant to leave (show_fresh's typed lines, `apply_ops(before, ops)`, a resume's `partial` + remainder), so typing that lands as an animation completes is never called clean; no expected content (`before=None`, a legacy `partial=None`) means no stamp. nvim's `:edit!` of a buffer that already has a swap runs no new swap search (measured, unlike Vim), so that re-read needs no swap toggle.
- **An adopted nvim (`adopt_existing`) is never locked `nomodifiable`** — animation or navigation. Guard every lock with `if self._locks_buffers()`, which fails CLOSED: true only when FollowerState proves a dedicated follower (`_is_dedicated()` via `state.owned_state`: readable, `adopted is False`, and naming THIS follower's backend and target — a racing `stop` + `start` writes a dedicated state for ANOTHER follower), so a state gone mid-hook (a racing `stop`) locks nothing; `_exec` passes `adopted=not self._is_dedicated()` for the same reason, and a `.pane` without `adopted` reads as adopted. The same holds on BOTH backends for `close_tab` (the dedicated `bwipeout!` runs only when `_is_dedicated()`; an unknown state takes the adopted eviction rules and logs one line, since a `stop` racing a Read once wiped the user's unsaved buffer) and `user_readonly` (unknown asks; on tmux only for an answer a readonly restore requested — the `readonly-<pane>.asked` mark, consumed on read — since a state-gone hand-off sends no restore). The tmux backend locks adopted Vim like a dedicated one; that asymmetry is intentional.
- **Closing a tab in an ADOPTED editor never wipes the user's work** (eviction past `max_tabs`, and `claude-follow stop`; final review C1, 2026-10-05: a Read put the user's own modified buffer into `open_files` and five Reads later `bwipeout!` took it). tmux `s:evict` / nvim `_EVICT_LUA`: a modified buffer (nvim: not clean by `_IS_CLEAN_LUA`) is "kept"; a buffer the follower did not create is never wiped — only a window the follower opened for it is closed, and the follower's Read lock is given back (`s:release`); a clean buffer the follower created is wiped, so max_tabs still caps its own tabs. "Created"/"opened" are editor variables (`b:vaf_created`, `w:vaf_opened`), never cache state: they must die with the editor, or a restarted adopted Vim's buffers would read as the follower's. Dedicated followers keep the plain `s:wipe`. Vim's `getwinvar()` takes a window NUMBER in the current tab — for a window id use `gettabwinvar` over `win_id2tabwin()` (a `getwinvar(id, …)` silently read '' and closed nothing).
- **show_fresh renames only a buffer it has PROVEN is new** (final review I1: a user `BufEnter … | tabfirst` on `:tabnew` made the rename name the USER's buffer, which the landing check then confirmed, since the rename makes any buffer "the target"). tmux `s:rename`: after `tabnew`, a number above every earlier one, unnamed, unmodified — else `s:drop_fresh` and no landing (NavigationFailed). nvim `_fresh_buffer`: `create_buf` + name by handle, put in the window of the tab the tabnew ADDED (found by tabpage handle), then require it current. Never "the current buffer after `:tabnew`".
- **tmux `:tab drop` ends with `:rewind`, whose abandon check runs on the buffer it just landed on** → E37 on a dirty target; wrapped in `try/catch`. Never `:tab drop!` (discards unsaved content). Swap-file dialogs are auto-answered "edit anyway" via a scoped `SwapExists` autocmd (tmux) / buffer-local `swapfile=false` before `bufload` (nvim) — `SwapExists` does not fire under `bufload`.
- **`:tab drop` on an UNMODIFIED buffer re-reads it from disk** (its trailing `:rewind` is an `:edit`). Every completed animation ends in `:e!`, so the buffer is clean, and by `hook post` Claude has already written the finished file: an Edit flashed the final content and then typed the diff on top of it (duplicated lines, def count 1 → 3 → 5 → 3), hidden from every end-state test because the relock's `:e!` snaps it back (bug since 3923bd0, fixed 2026-09-23). tmux `goto_file` now switches to a loaded buffer by NUMBER (`win_gotoid` / `:tab sbuffer N`) and keeps `:tab drop` only for a file no buffer holds. The old reload was also silently clearing `readonly`, so the animation unlock now says `noreadonly` itself — without it, `o` on a buffer show_fresh/ensure_showing locked raises W10 and a hit-enter prompt eats the whole animation. In an ADOPTED Vim only (a dedicated follower's readonly is never the user's), the follower marks its own claim on the option in `b:vaf_ro_ours` (1 = its readonly lock, 2 = unlocked for an animation), notes the user's value in `b:vaf_user_ro` (and 'modifiable' in `b:vaf_user_ma`) before each of its readonly-changing steps while it holds no claim, and `s:restore_readonly` puts the user's back after the relock, at an interrupt and in `hand_over` (a recorded 'nomodifiable' too; the eviction's `s:release` puts back the recorded 'modifiable'). 'paste' is GLOBAL: every unlock records the user's in `g:vaf_user_paste` (unless the run already holds it), an interrupt and `hand_over` give it back — only from that record (`s:hand_over`: no `g:vaf_user_paste`, no give-back; an adopted Vim gets 'modifiable' back only with a `b:vaf_user_ma` record), since the interrupt's paste restore (`_RESTORE_PASTE`) has already consumed it and a second give-back from no record set the user's paste to 0 — and the completion relocks forget the record. Never a changedtick stamp: a reload (`:checktime` under 'autoread') moves the tick but keeps the follower's readonly, and it was handed back as the user's (E45 on the cue's `:w`). The restore also writes `user_readonly`'s answer to a file, so the `:w!` hand-off cue costs no keystrokes of its own; the answer closes with the restore's six-digit token (a bare Vim number: no leading 0, which Vim reads as octal) and only the token this process sent counts, since the file is named by the pane id alone and two tmux servers can share one. `tests/test_integration_edit_no_reload.py` watches the buffer MID-animation with a VIMINIT-loaded Vim timer (no keys sent) — assert on the middle, not just the end. The one navigation that SHOULD re-read is a Read (`ensure_showing`): it adds a clean-only `silent edit` (`s:reload`) so a file rewritten by Bash/`sed -i`/`git checkout` isn't shown stale — and that `:edit` re-runs the swap search and raises ATTENTION on its own when the user's Vim owns `.swp`, so it carries the same scoped SwapExists answer.
- **The tmux backend types only short calls — its Ex logic is Vim functions defined once per Vim, and the target's path is never on a typed line.** Vim echoes every typed command on its command line: the demo flashed the absolute path on every edit (2026-09-29), and later a 12–30-row block of Vim script (the ~1,500-character goto line, 2026-10-05). The logic lives in `tmux_vim._VIM_SCRIPT` (legacy Vim script, every function `abort` so an error stops it where it used to stop the rest of a typed line, helpers script-local, ONE global dispatcher `VafFollower_<6 hex>` named after a hash of the script + cache dir), written to `CACHE_DIR/vaf-<hash>.vim` (the dispatcher is defined only once every `s:` helper and the preamble's `s:dir` exist, because `:source` carries on past an error under `sil!`; `_script_file` touches the current script on every define, and `_sweep_scripts` deletes the cache dir's other scripts unused for a day and cut-off `.vaf-*.vim.<hex>` temporaries older than 600 s — no Vim needs a script it already sourced, only the next define of a Vim that lacks the dispatcher reads it) and sourced by `_define_line` (`:if !exists('*VafFollower_…')|sil! so ~/.cache/…|endif`), which every entry point that may be first sends before its calls — so a Vim that lost the functions (`:delfunction`, an adopted Vim restarted in the same shell: same pane pid) gets them on the very next call; the script deletes older dispatchers, but only one Vim says was set from `vaf-<its own hash>.vim` in THIS cache dir (`:verbose function`'s path — its words are translated — compared with `fnamemodify(resolve(…), ':~')`, because Vim records a script symlink-resolved and shows it `~/…` under its HOME; a literal `s:dir` match never fires), so a user's own `VafFollower_123abc()` survives, even from a file named `vaf-123abc.vim` elsewhere, and a hand-pasted dispatcher (no file) is the user's code and stays. Each call line is `:if exists('*Fn')|call Fn('op',…)|endif`, no spaces around the bars: two screen rows at 49 columns is ≤ 97 typed characters with the `:` (96 from `getcmdline()`; measured on Vim 9.2, `:` + 97 puts the cursor on a third row), the longest is show_fresh's rename, whose handle carries the pane id, and it must fit up to six-digit pane ids (pinned by `tests/test_integration_cmdline_paths.py` and the unit `test_every_typed_call_fits_two_screen_rows`), so a Vim without them runs nothing and raises no E117. A path reaches Vim through a handle file per call (`_path_handle`, `p<pane>-<6 hex>`, also the call's token): `s:read` reads it byte-exact (`filereadable()` + `readfile(…, 'b')`, never a try around the read) and `delete()`s it (never a fixed per-pane file — Vim runs a line after the send returns, so an eviction and the next pre-wipe would share it; unread handles are swept after 600 s, any pane's). A missing handle reads as '' and every function then acts on nothing; a call that must ACT (`s:goto`, `s:rename`) is followed by an Escape pair and a separate `s:landed` call (never the acting call's tail — a goto that opens a second tab from one leaves a prompt that swallows the next line's first screen row) that answers `landed-<pane>.txt` only when the current buffer is the one the acting call recorded landing on (`g:vaf_landed`, by NUMBER, next to the token `g:vaf_k`), and Python sends nothing more without it (`NavigationFailed`, which the hooks log in one line and skip the edit, marking the file stale) — a failed goto once let a Read lock, and an Edit's relock `:e!` wipe, the user's own unsaved buffer. Never confirm by re-deriving the target's NAME: Vim navigates by file identity (`:tab drop` lands on an existing buffer opened through a file symlink, e.g. a dotfiles `~/.vimrc`, or under a case variant on macOS), and a name check failed every Read of such a file after 10 s. The script names the cache dir in full (`s:dir`; a file, never echoed), so only the define line types a path: `~/.cache/…` when the pane's Vim shares the hook's HOME — asked once per pane pid (`_vim_shares_home`, `:silent! call writefile([], expand(…, 1))`; the `1` (nosuf) is load-bearing, since a `wildignore=*/.cache/*` makes a plain `expand()` return ''; `:source ~/…` itself ignores 'wildignore', measured; an adopted pane's pid is the user's SHELL, so no answer with the path handle still unread drops a "yes" and the next call asks again), else the absolute path (through `fnameescape()` unless it is plain); when the guarded absolute form passes 97 characters (117 for a plain `/Users/…/.cache/…`), the guard is dropped (`:sil! so <path>`, re-sourced on every call, ~0.2 ms; the script keeps no state of its own — and its body is wrapped in `if 1`…`endif`, because a Vim without +eval, e.g. vim-tiny, runs every function BODY as top-level Ex commands and empties the user's buffer; `tests/test_tmux_typed_path.py` proves it in Docker), and past an 88-character script path the guarded form stays and logs it once per pane (`define-rows-<pane>`, marked used on every such line and swept a day after last use, like old scripts). Commands that print a file's name are `silent` (`:file`, `:tab drop`, `:tab sbuffer`), errors still showing. `tests/test_integration_cmdline_paths.py` logs every `CmdlineChanged` plus `:messages` — never pass `_vim_string(file_path)` into a typed line.
- **Every typed line and its Enter go in ONE `send-keys` (`TmuxPane.send_line`: the CR inside the `-l` text).** With the Enter in a second subprocess Vim drew the line, flushed and waited for it: measured 2026-10-17 from Vim's raw terminal output (`pipe-pane` into a timestamped recorder, 49 columns, 400 calls), every line stayed on screen 3–64 ms (median 6 ms, 15 ms under load; a canary with a 50 ms gap read 55–150 ms); in one write Vim reads both and executes before it flushes, so the line's bytes still reach the terminal but in the same write as the redraw that replaces it — 1–3 of 400 still showed for over 1 ms (1.5–64 ms, the longest under load), each one a line Vim read in two parts. Never join the Enter as `\; send-keys Enter` (the semicolon rule below). **And a line that has RUN stays drawn**: Vim leaves a typed Ex command on its bottom row until something redraws it, which the input-gap measurement cannot see (review I1 of T23: `:setlocal readonly nomodifiable` after every Read; in a pane wide enough for a call to fit one row, 12 of 12 calls, adopted Vims included; `goto_line`'s `:N` everywhere). The dispatcher ends with `redraw` + `echo ''`, and so does every plain line that can be the last one an entry point types (`_cleared`, `_CLEAR_COMMAND_LINE`): `redraw` alone keeps the line, a bare `echo ''` after a command that printed raises a hit-enter prompt (`:1|echo ''`, since a range before a bar PRINTS the line — so goto_line types `:exe N`), `redraw!` repaints the screen. An adopted Vim's plain relock skips the tail (the readonly restore, a call, always follows, and the claim plus the tail passes 97 characters). `tests/test_integration_command_line_clear.py` reads the bottom rows 300 ms after each call at 49 and 200 columns. Unit tests see each line as `send_text` + `send_key("Enter")` through conftest's `typed_lines_as_text_and_enter`; `@pytest.mark.real_send_line` opts out, and `test_no_typed_line_waits_for_a_separate_enter` runs every entry point that way, completed and interrupted, dedicated and adopted. animate.py's paced `:Nd`/`:N` + Enter pairs stay separate on purpose (they are the visible animation).
- **tmux ends a command at ANY argument that ends in `;`, and drops that `;`** — so `send-keys -l -- 'int a = 1;'` types `int a = 1`, a lone `;` types nothing, `c;;` types `c;`, and a final `\;` types `;` (where the `;` is dropped, a backslash left at the end becomes the `;`). Typed file content hit it: an interrupted Write's `:w` saved every `;`-ending line without its `;` and the hand-off released Claude (review C1 of T23, measured on tmux 3.8, 2026-10-17). `TmuxPane.send_text` sends a final `;` as `\;`, which is exact for every string measured (23, multibyte, tab, `#{`, a leading `-` and a trailing `\` included); `-H` hex was exact too, at one argument per byte. Every user-content path goes through `send_text` (animate's `send_paced`; `send_key` only ever gets key names); `send_line`'s argument ends in `\r` and never needs it. The escape is one helper, `tmux.literal_argument`, used by `send_text` and `set_title` (the user's saved pane title, restored by `StatusSurface.clear()`: `vim x;` came back `vim x`). `keybindings.unregister` no longer rebuilds an argv for a user's own binding (shlex lost chains, brace blocks — which then failed to bind and left OURS bound — and `"\$HOME"`; T24a review m4): it writes the saved list-keys line to a temp file for `source-file`, verbatim except that a `\;` token followed by nothing, another `\;` or `}` is a literal `;` key and goes as `'\;'` (list-keys prints `send-keys '\;'` and a chain separator alike), then requires `list-keys` to show the same line (a multi-line brace block lists `a ;; b` and re-lists `a ; b`, treated as equal); anything else unbinds the key and logs one line naming the binding. `send-keys a '\;' b` is undecidable from its listing (`send-keys a \; b`) and is the logged case (`tests/test_integration_binding_restore.py`). Other argv checked and safe: option values (follower-chosen or the saved `pane-border-status` enum), border colours, pane ids, formats, the nvim split command (ends in the socket path). `tests/test_integration_typed_semicolon.py` (a real Vim, the dedicated `:w` hand-off and an adopted VIMINIT-observed animation) fails with the old sender. A pane title has two more transforms (T24b): `select-pane -T` FORMAT-EXPANDS its argument (`#{pane_id}` set as `%0`, `#S` as the session, `##` as `#` unless a `[` follows the run, a final `#` dropped), and tmux STORES a title vis-encoded (a backslash as two, from OSC 2 too) and `#{pane_title}` prints the stored form, so a saved `a\` doubled on every save/restore; `TmuxPane.title()` turns each stored backslash pair back into one and `set_title` sends every `#` as `##` EXCEPT a run of `#`s that ends at `[`, which tmux keeps whole (`#[fg=red]x`, `##[x` stay as typed; doubling them grew a style title by a `#` per `#` on every cue, T24b review I1) (`tests/test_integration_pane_title_round_trip.py`, titles set by OSC 2 in a real pane, three cue cycles).
- **On tmux, whether a navigation landed is the landing check's to say, never an error's.** `s:goto` catches EVERY error (not only E37) into `g:vaf_nav_error`, which `s:landed` writes between verdict and token and the hook logs: a user `BufReadPost` `echoerr` aborted the `abort` function before the landing was recorded, so every Read of a file no buffer held answered "elsewhere" (measured 2026-10-06). show_fresh's `:file` is caught the same way: not landed (E95, a throwing BufFilePre), its buffer gets swap back and a tabnew's empty buffer goes (`s:drop_fresh`); a BufFilePost throw has already renamed, so it lands. The ownership marks (`b:vaf_created`, `w:vaf_opened`) are set AFTER the try, under the landing proof: inside it a caught error skipped them and an adopted eviction kept the follower's tab as the user's. A landing left UNANSWERED backs the pane off for 30 s (`unanswered-<pane>` in the cache dir): goto_file/show_fresh raise NavigationFailed at once and probe_buffer is "unknown", with nothing sent; close_tab is the exception, sent with no define line and no wait for a verdict, because skipping it left an adopted Vim's own buffer locked for good after `stop`. A landing ends the backoff, a mark more than 2 s in the future is removed (a clock set back held it for the whole step), and a HOME distrust takes precedence (no backoff: the next call re-asks and heals). The trigger is a BLOCKED Vim (`:!make`, `:sleep`), not the cmdwin: there the typed calls run and answer "elsewhere" at once (measured, Vim 9.2). A post-pause goto that fails mid-animation re-saves the remainder before re-raising (`animate._resume`; cmd_pause keeps it; both drop it when a `stop` cleared the state meanwhile), and `_with_unlocked` gives back 'paste' and, adopted, the ANIMATED buffer's readonly by handle (`s:give_back`), never the current buffer's.
- **macOS Vim has 'fileignorecase' ON by default — never let it decide whether two names are one file.** On a case-sensitive volume `Readme.md` and `README.md` are two files, and with it on the lookups, `:tab drop README.md` and `:file README.md` all took the one for the other (an Edit typed into the sibling, a retype wiped it, an adopted Read locked the user's modified sibling; measured 2026-09-29 on a Case-sensitive APFS image). The tmux backend's lookups (`s:find`/`s:same_file`) compare `resolve()`d `:p` names with `folds`, which Python decides per path from the FILESYSTEM (`_case_folds`: is the swapcase spelling the same file); the acting functions run with `&fic` off (restored in `finally`), so Vim matches by inode; a landing counts only when the current buffer IS the target by that comparison (a hard link lands "elsewhere"). `resolve()` of a symlink loop raises E655, so every resolve is in its own try (`s:resolved`) inside a `:for` — one looping buffer in a `filter()` aborted every lookup. `tests/test_integration_same_file.py` attaches a real case-sensitive disk image (hdiutil; skipped without it). The same folds keep a wrong-CASE hook path found after a `:cd`/`:lcd`/`:tcd` re-bases Vim's name to the on-disk case (forcing folds to 0 turns `test_a_hook_path_spelled_unlike_the_disk_is_found_after_a_cd` red). Unicode normalization is NOT folded anywhere: Vim keeps the bytes it was given (`resolve()`/`:p` of an NFD name stay NFD), so a buffer the user opened as `Café.py` in NFC is not the hook's NFD spelling: probe "absent", the Edit fails safe with `NavigationFailed` (measured 2026-10-06). Canonicalizing the hook path with macOS `F_GETPATH` (which does return the on-disk case and normalization) only moves that mismatch to users who typed the other form, so it was not adopted.
- **Renaming a buffer onto a path marks it "not edited"** (Vim `:file`, nvim `buf_set_name`): a plain `:w` over the existing file then fails with E13, which made the hand-off cue's ":w releases" false for an interrupted Write. show_fresh reads the file in and clears it in the SAME call / nvim request (tmux `s:rename`, nvim `_READ_THEN_CLEAR_LUA`: `noautocmd silent! edit!` then `silent! %d _`), so it is never on screen; with the buffer's 'undolevels' at -1 for that one step (nvim: saved raw and restored around the request; tmux: `setlocal undolevels=-1` restored in `finally`), so the read-in file is never an undo step (on Vim undoing it never showed the content, but the step held the file in memory); this is the one `:edit` the nvim backend runs outside ensure_showing, on the empty buffer it just created. The read also restores the "changed since reading it" check a not-edited buffer skipped.
- **Pause/interrupt signals are addressed to the animating PID** (`control._request` writes the live marker's PID; `check_signal` obeys only its own and drops the rest as stale). Never clear signals when a driver starts: the hook shows "running" from `try_acquire_animating` on, navigates first, and a start-of-driver `clear_signals` wiped every P pressed in that gap (lost 5 of 5 runs, fixed 2026-09-28). A test that calls `request_pause` needs a live marker first (`mark_animating`), or nothing is written (`_request` returns False). What drains instead: the hook's exit (`_drain_unconsumed_signals`, Edit and Read) marks "finishing", consumes what is addressed to it and takes the press's feedback back — nvim retires "Paused" from the float, tmux shows "Nothing to pause" only after the press's own popup closed (tmux drops a popup opened while another is up, silently, exit 0). The marker reads "handoff" from the moment an interrupted driver returns, BEFORE the remainder is saved (tests that read the remainder wait for both: `wait_for_handoff`), "running" from the moment the hand-off wait consumes the S, and "finishing" before the hand-off cue comes down. Order: read the state raw (unreadable counts as none; with no state, the `<window>.stopping` record a killed stop left), copy it to `<window>.stopping`, `mark_stopped` (`<window>.stopped`: the tmux server pid, from `tmux_server_pid_from(env)` which falls back to `$TMUX`'s pid field; '' standalone; `unknown` inside tmux when no pid can be learned), `FollowerState.clear` + signals + pending, then the teardown, then a second `clear` (a writer that passed `set`'s check mid-stop), then the `.stopping` record goes, then the keybindings. Every teardown step is logged, never raised: `stop` always exits 0 (a frozen or prompting nvim used to exit 1 with the `.pane` left, so the next hook drove it again). Under the tombstone `FollowerState.set`/`update` write nothing (`set` returns False) and `_maybe_auto_open` returns None (one hook.log line per window, `<window>.stopped-noted`; a window never stopped costs one stat, no tmux spawn); a hook that launched an editor and then had its write refused closes what it launched (`hooks._launched_follower`, never an adopted nvim). Only `start` (in `_record_start`, right before the write, so a failed start keeps the stop; also when the follower is already running) and toggle clear it. `is_stopped`: '' holds always, a caller with no server pid is held (fail closed), otherwise only the recorded pid holds, so an `unknown` tombstone never holds under a known server: window ids are reused across tmux restarts. **Every state records the tmux server it was written under** (`FollowerState.server_pid`, measured by `set` for a tmux follower or one with an origin, kept by `update`), because after a tmux restart pane ids start again from %0 and a surviving `.pane` names somebody else's pane (final review C1/C2: `stop` killed Claude's own pane and typed Vim script into a shell). `get`, the reopen and toggle drop a state from ANOTHER server (`from_another_server`, lenient: an unknown pid proves nothing); `stop` acts only on proof (`proven_here`: recorded pid == current), else it clears the state with one hook.log line and sends nothing, so a legacy state with no pid is never torn down; the tmux teardown then also requires `is_alive()` (the pane still runs vim) before close_tab or kill. In tests the autouse `no_real_tmux_server` fixture unsets TMUX/TMUX_PANE and points TMUX_TMPDIR at an empty dir (every test: `tmux_session` overrides it), and the e2e harness isolates only its subprocesses, so an in-process `FollowerState.set` there passes `server_pid=world.server_pid`; unit mocks answer `display-message -p #{pid}` with `MOCK_SERVER_PID`. The nvim teardown is one probe plus CONNECT + RPC timeouts (13 s) for everything, the pane close included: the RPC steps end its two 1 s graces early (`rpc_ends_at`); it sends NOTHING to a silent/absent/garbled nvim or to an ADOPTED one waiting on its user (keys pending, a confirm, the command line, an operator pending, the command-line window, insert/replace/terminal/visual/select mode — `adopted_user_pending`, asked once — or a prompt the sweep cannot reach); an adopted one at a hit-enter/more prompt is swept first and then torn down (T22); its RPCs go to the state's socket whatever the server (the follower's own file), but its pane close needs `proven_here`. Since the state is gone by teardown, `close_tab`/`stop` take `dedicated=` from the caller (None reads the state, failing closed). A DEDICATED nvim that did not quit has its own pane closed — found in the origin's window by the exact start command `nvim --listen <socket>` (shlex), never the origin, never an adopted pane — and any of the pane's recorded processes still alive after 1 s whose command line names the socket is SIGKILLed: an nvim busy in `:!cmd` leaves its `--embed` server running when its pane goes, through SIGHUP and SIGTERM (measured 2026-10-16).
- Test-side: assert on the specific call, not `assert_called_once` — exact call counts break whenever a neighbor adds an API read.
- **Run the full suite alone.** Integration tests spawn real tmux servers and nvims; two suites in parallel (or a parallel agent's) push load past 10 and produce false timeouts — rerun the failing test alone before calling it a regression.
- **QA scripts (`scripts/qa-check-*.sh`) must run from inside a tmux pane** (`$TMUX_PANE` guard) and background a hook with `> log 2>&1 &`, never `| tee` — a pipe makes the shell wait and the interrupt/pause you're testing never lands. Finish with `source scripts/qa-lib.sh && qa_teardown`.
- **`conftest.py`'s autouse `no_pid_ancestry_walk` only reaches IN-PROCESS code.** It stubs `session._tmux_panes_by_pid` so the suite doesn't resolve to whatever window the developer is sitting in — but a test that runs the hook as a SUBPROCESS bypasses it and the pid walk hits the real tmux server. Point such a test at a private socket and fire the blind half from the pytest process, not from inside a pane, or it passes for the wrong reason. Opt in with `@pytest.mark.pid_walk`.
- **`tmux` and `keybindings` share one `subprocess` module object**, so patching `vim_ai_follower.tmux.subprocess.run` silently intercepts `keybindings`' `git rev-parse` too. Resolve any expected path INSIDE the patch, or expectation and code under test see different worlds.
- **Coverage is blind to subprocess execution**, so the e2e CLI tests add none — expect the percentage not to move, and never chase it with `# pragma: no cover`. To read a real buffer from an integration test, dump it with Vim's `writefile()` (or `buf_get_lines` over RPC): delete the dump first and wait for a sentinel prefix so a stale or half-written read can't pass for an answer, and retry — a loaded machine swallows the ESC pair.
- **Worktrees:** tool-created worktrees may start from a stale `origin/main` — check `git rev-parse HEAD` against local `main` first. `docs/superpowers/` is gitignored, so edits made there inside a worktree never come back via merge: copy them to the main checkout before removing the worktree.

## Release

`claude plugin update` is gated on `.claude-plugin/plugin.json`'s `version`, not on git. Every user-visible fix: bump the version, commit, then `claude plugin tag --push` (creates `vim-ai-follower--vX.Y.Z`; refuses a dirty tree — never `--force`). CI is `ci.yml` (unit suite + coverage floor) and `lint.yml` (ruff + mypy); the README coverage badge is static — update it in the same commit when the measured number moves.

- `scripts/validate_plugin.sh` (run first by `full_suite.sh`, skipped without `claude` on PATH) is `claude plugin validate --strict .` tolerating exactly one warning: "CLAUDE.md at the plugin root is not loaded as project context" — this file is the repo's notes for Claude Code, not plugin context, so it stays. Any error or other warning fails. Not in CI: it needs the Claude Code CLI.
- `git fetch` before pushing main: Dependabot/deps PRs merge on GitHub (`uv.lock` bumps), so origin/main moves without you; merge it, rerun lint + unit on the merged tree, then push.
- `docs.yml` builds with `uv run`, and `[tool.uv] python-preference = "only-system"` + `.python-version` (3.14) means the job must install THAT Python (`python-version-file`); with 3.11 every `uv run` failed. Pages is enabled with `gh api -X POST repos/albertosca/vim-ai-follower/pages -f build_type=workflow` (done 2026-10-05).
- The GitHub runner is slower than the Mac: a thread race the local suite never lost failed CI (the nvim watchdog counted a dismissal after its settle wait, c6b0dc5). A timing-dependent unit test must make the slow interleaving deterministic, not hope for the fast one.
